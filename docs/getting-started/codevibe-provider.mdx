The **Codie provider** path centralizes sign-in and model selection for Codie.

Use any configured Codie-supported provider. When compatibility support is enabled, Codie can also import local auth files such as `~/.codex/auth.json`.

## Why use Codie provider settings

- **Fast setup**: use Codie sign-in or optional local auth import without manual API key copy/paste
- **One model picker**: choose recommended, cloud, BYOK, or local models from one place
- **Compatibility**: legacy provider IDs can remain internally so existing profiles and upstream patches keep working

## Setup

<Steps>
  <Step title="Open Codie Settings">
    Click the settings icon in the Codie panel.
  </Step>

  <Step title="Choose Provider">
    Set **API Provider** to your Codie-managed provider, or choose another configured provider.
  </Step>

  <Step title="Verify Auth">
    Confirm `~/.codex/auth.json` exists, or click **Sign In** for a hosted provider flow.
  </Step>

  <Step title="Select a Model">
    Choose a model from the **Model** dropdown.
  </Step>

  <Step title="Verify">
    Send a test message. If Codie responds, setup is complete.
  </Step>
</Steps>

## Account and usage

- Codie sign-in uses the configured hosted account flow.
- Local auth import uses your existing local account/session files when enabled.
- View configured account and usage surfaces in Codie Settings when available.
- Switch organizations from the provider account menu when the active backend supports it.
