The **CodeVibe provider** path is the simplest way to get started with CodeVibe.

By default, CodeVibe reads your local Codex auth from `~/.codex/auth.json`. If a hosted CodeVibe account backend is configured, you can also sign in once and select from available models directly in CodeVibe.

## Why use CodeVibe provider settings

- **Fastest setup**: reuse Codex auth without manual API key copy/paste
- **One model picker**: choose Codex, OpenAI-compatible, Anthropic, Gemini, or local models from one place
- **Compatibility**: legacy provider IDs can remain internally so existing profiles and upstream patches keep working

## Setup

<Steps>
  <Step title="Open CodeVibe Settings">
    Click the settings icon in the CodeVibe panel.
  </Step>

  <Step title="Choose Provider">
    Set **API Provider** to **OpenAI Codex** for the default Codex auth path, or choose another configured provider.
  </Step>

  <Step title="Verify Auth">
    Confirm `~/.codex/auth.json` exists, or click **Sign In** for a hosted provider flow.
  </Step>

  <Step title="Select a Model">
    Choose a model from the **Model** dropdown.
  </Step>

  <Step title="Verify">
    Send a test message. If CodeVibe responds, setup is complete.
  </Step>
</Steps>

## Credits and usage

- Codex auth uses your local Codex account/session.
- View configured account and usage surfaces in CodeVibe Settings when available.
- Switch organizations from the provider account menu when the active backend supports it.
