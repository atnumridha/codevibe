Codie configuration lives in two scopes:

- **Global configuration** in `~/.codevibe/` (applies globally across Codie applications, including IDE, CLI, and SDK)
- **Project configuration** in `.codevibe/` (applies only to the current workspace)

## Configuration Directory Layout

Codie stores shared configuration across a few well-known locations. The primary root is `~/.codevibe/`, with structured app state under `~/.codevibe/data/`:

```text
~/.codevibe/
  data/
    settings/
      providers.json           # API keys and provider configuration
      global-settings.json     # Global settings
      codevibe_mcp_settings.json  # MCP settings
    teams/                     # Team state
    sessions/                  # Session data
    db/                        # SQLite databases (for example cron.db)
    workflows/                 # Global workflows
  rules/                       # Global rules
  hooks/                       # Global hooks
  skills/                      # Global skills
  agents/                      # Global agent definitions
  plugins/                     # Global plugins (.js, .ts)
  cron/                        # Global cron specs
```

Additional legacy global search paths supported for compatibility:

```text
~/Documents/Cline/
  Rules/                       # Additional global rules
  Hooks/                       # Additional global hooks
  Plugins/                     # Additional global plugins
  Workflows/                   # Additional global workflows
```

Project-level configuration lives in `.codevibe/` at your repository root:

```text
.codevibe/
  rules/                       # Project rules
  skills/                      # Project skills
  hooks/                       # Lifecycle hooks
  agents/                      # Project agent definitions
  plugins/                     # Project plugins
  cron/                        # Workspace cron specs
```

Notes:

- Global provider settings, global settings, and MCP settings are stored under `~/.codevibe/data/settings/`.
- Global workflows resolve from `~/.codevibe/data/workflows/` or the configured Codie data directory.
- Global rules, hooks, skills, agents, plugins, and cron specs resolve directly under `~/.codevibe/`.
- Legacy `~/.cline/` and `~/Documents/Cline/` locations may still be discovered for compatibility.

## What Goes Where?

- Use **global (`~/.codevibe/`)** for defaults shared across all Codie applications (IDE, CLI, SDK) on your machine.
- Use **project (`.codevibe/`)** for team-shared behavior that should travel with the repo.

Commit `.codevibe/` files you want to share with your team. Keep secrets out of the repo. Legacy `.cline/` files remain supported for compatibility.

## Configure Through the CLI

Use the interactive config UI:

```bash
codevibe config
```

From there, you can view/edit:

- Settings (global + workspace)
- Rules
- Skills
- Hooks

## Useful Configuration Commands

Use a custom configuration directory:

```bash
codevibe --config /path/to/custom/config "your task"
```

Or via environment variable:

```bash
export CODEVIBE_DATA_DIR=/custom/path/to/codevibe
codevibe "your task"
```

View CLI logs when troubleshooting:

```bash
codevibe dev log
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `CODEVIBE_DATA_DIR` | Custom data directory |
| `CODEVIBE_HUB_ADDRESS` | Override hub address (default: `127.0.0.1:25463`) |
| `CODEVIBE_SESSION_BACKEND_MODE` | Force backend mode (`local`, `hub`, `remote`, `auto`) |
| `CODEVIBE_SANDBOX` | Enable sandbox mode |
| `CODEVIBE_SANDBOX_DATA_DIR` | Sandbox session storage directory |
| `CODEVIBE_HOOKS_DIR` | Additional hooks directory |
| `CODEVIBE_COMMAND_PERMISSIONS` | JSON policy restricting shell commands |

Legacy `CLINE_*` variables are accepted as compatibility aliases when the matching `CODEVIBE_*` value is not set.

### CODEVIBE_DATA_DIR

```bash
export CODEVIBE_DATA_DIR=/custom/path/to/codevibe
codevibe "your task"
```

### CODEVIBE_COMMAND_PERMISSIONS

Restrict which shell commands Codie can execute:

```bash
export CODEVIBE_COMMAND_PERMISSIONS='{"allow": ["npm *", "git *"], "deny": ["rm -rf *"]}'
```

Format:

```json
{
  "allow": ["pattern1", "pattern2"],
  "deny": ["pattern3"],
  "allowRedirects": true
}
```

Rules:

- `deny` overrides `allow`
- If `allow` is set, commands not matching `allow` are denied
- `allowRedirects` controls shell redirects (`>`, `>>`, `<`), default `false`

## Security Notes

<Warning>
Only use rules, hooks, skills, and plugins from sources you trust.
</Warning>

Hooks and plugins can execute code. Review them like any other executable artifact before adding them globally or to a project.
